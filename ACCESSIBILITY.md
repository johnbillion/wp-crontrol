# WP Crontrol Accessibility Statement

WP Crontrol aims to be fully accessible to all of its users. It implements best practices for web accessibility, outputs semantic and structured markup, adheres to the default styles and accessibility guidelines of WordPress, uses the accessibility APIs provided by WordPress and web browsers where appropriate, and is fully accessible via keyboard and via mobile devices.

## Standards

WP Crontrol targets compliance with the [Web Content Accessibility Guidelines (WCAG) 2.0](https://www.w3.org/TR/WCAG20/) at level AA when used with a recent version of WordPress where the admin area itself adheres to these guidelines.

## Supported environments

WP Crontrol runs entirely within the WordPress admin area and inherits the browser, assistive technology, and device support of WordPress itself. Its screens are built with the standard WordPress admin markup and styles, with a small amount of plugin-specific CSS and JavaScript.

## Known barriers

There are no known accessibility barriers in WP Crontrol. If you encounter one, please report it using the process below.

## Reporting accessibility issues

If you find an accessibility problem in WP Crontrol, please [open an issue on the GitHub repository](https://github.com/johnbillion/wp-crontrol/issues). Include the version of WP Crontrol and WordPress, your browser, and any assistive technology you were using.

## Contributing

Contributions which improve the accessibility of WP Crontrol are very welcome. See [the contributing guidelines](CONTRIBUTING.md) for details on how to get started.
